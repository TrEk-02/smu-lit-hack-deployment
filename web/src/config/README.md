# Configuration

Legal owns the contents of this directory. Code imports it; code does not
duplicate it. Any substantive rule change is recorded in `DECISIONS.md` as
well (working agreement §6).

## `rules.json`

The single source of eligibility truth: general gates, per-category gates, and
the party/filing intake fields. Validated against `RulesFileSchema` at import
time by `src/lib/rules.ts` — a malformed file throws on boot, naming the
offending gate id, rather than producing a wrong verdict at runtime.

Only `status: "published"` gates are evaluated, offered to the LLM, or shown.

| Field | Meaning |
|---|---|
| `id` | Stable gate identifier. Keep it when editing the wording. |
| `status` | `draft` or `published`. Drafts are inert. |
| `description` | Legal's internal note. Never sent to the model or the browser. |
| `field` | Answer key. Shared fields must agree on `answerType` across gates. |
| `answerType` | `boolean` \| `number` \| `select` \| `date` \| `text` |
| `options` | Required for `select`: `{ value, label }`. |
| `operator` | One of nine, including `withinDays` for limitation periods. |
| `value` | Comparison target, typed to match `answerType`. |
| `onFail` | `FAIL` \| `CONDITIONAL` \| `WEAKNESS`. |
| `plainExplanation` | Shown when the gate does not pass. |
| `passExplanation` | Optional, shown when it does — keeps permission instructions off a passing gate. |
| `missingMessage` | Question asked when the answer is absent. Feeds the challenge round. |
| `appliesWhen` | Prerequisite answers. Shared by form visibility and server-side evaluation. |
| `source` | Title, provision reference, URL. Looked up by gate id after validation — never generated by the model. |
| `evidence` | See below. |

### `evidence`

A discriminated union on `checkable`, so a block cannot be half-filled.

- `checkable: false` → requires `reason` (why no document could speak to it).
- `checkable: true` → requires `expect` (what a document would have to show —
  this string drives finding quality), plus `docTypes`, `correctable`, and
  `onContradiction` (`CORRECT` | `ESCALATE`, defaulting to `CORRECT`).

`correctable: true` with `onContradiction: ESCALATE` is rejected by the schema.

The model receives only `{ id, question, userAnswer, expect, answerFormat }`.
It never sees `operator`, `value`, `onFail`, `source` or `plainExplanation`, so
it cannot tell which answer passes and cannot invent a provision.

## `scenarios.json`

Demo fixtures for Scenario A and Scenario B — answers only. Deliberately
separate from `rules.json`, which throws on a typo; a mistake in demo data must
not take down the app. The buttons fill inputs; the verdict and the document
findings are still computed live. Sample PDFs are supplied manually at demo
time and are not stored in the repo.

`src/lib/scenarios.test.ts` asserts each scenario's expected verdict, so a
`rules.json` edit cannot silently break the demo.
